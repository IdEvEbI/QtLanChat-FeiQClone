### 05-if-branch.md - 分支结构详解

#### 🔑 核心知识点

- **单分支（if）**
  - 语法：`if (条件) { ... }`
  - 条件为真时执行
  - 类比：如果...就...

- **双分支（if-else）**
  - 语法：`if (条件) { ... } else { ... }`
  - 两个分支必执行其一
  - 类比：如果...否则...

- **多分支（if-else if-else）**
  - 语法：多个 `else if` 和最后的 `else`
  - 从上到下依次检查
  - 找到匹配后停止
  - 最佳实践：else if 建议不超过 3-5 个

- **嵌套分支**
  - 在 if 或 else 内再嵌套 if-else
  - 嵌套层级建议不超过 2-3 层

- **三元运算符（条件运算符）**
  - 语法：`条件 ? 值1 : 值2`
  - 如果条件为真返回 `值1`，否则返回 `值2`
  - 是 if-else 的简化形式，只能用于赋值或返回值
  - 适合场景：简单的双分支赋值
  - 不适合场景：复杂的逻辑判断、需要多行代码的情况
  - 可读性：虽然简洁，但可读性不如 if-else
  - 使用建议：初学者优先使用 if-else，熟练后再使用三元运算符
  - 类比：就像"如果下雨就带伞，否则带雨衣"，用三元运算符就是 `下雨 ? 伞 : 雨衣`
  - 示例：`int max = (a > b) ? a : b;` 等价于 `if (a > b) max = a; else max = b;`

- **条件表达式**
  - 条件必须是 `bool` 类型
  - 可以是比较运算或逻辑运算

- **重要规则**
  - else 只能有一个
  - else if 可以有多个
  - 大括号使用建议（始终使用大括号）
  - 执行顺序（从上到下）

- **最佳实践**
  - 避免过深嵌套
  - else if 数量控制
  - 条件过多时考虑 switch（预告）

- **用户输入**
  - `std::cin` 在条件判断中的应用
  - 交互式程序设计

#### 🎓 教学特色

- **类比**：分支结构像交通信号灯
- **类比**：if-else if 像单选题，多个 if 像多选题
- **类比**：嵌套像层层权限验证
- **类比**：三元运算符像"如果下雨就带伞，否则带雨衣"的简化表达

### 06-while-loop.md - while 循环详解

#### 🔑 核心知识点

- **while 循环基础**
  - 语法：`while (条件) { ... }`
  - 只要条件为真就重复执行
  - 先判断后执行（循环体可能一次都不执行）

- **循环的特点**
  - 条件检查：循环开始前和每次循环结束后都会检查
  - 条件必须改变：避免无限循环
  - 适合不确定次数的重复任务

- **循环变量**
  - 需要在循环外初始化
  - 需要在循环内更新（改变条件）
  - 类比：开车前检查油箱，从起点开始

- **关键规则**
  - 必须有改变条件的语句（如 `count++`、`value--`）
  - 否则会陷入无限循环
  - 类比：忘记关水龙头，水会一直流

- **常见应用场景**
  - 计数循环：从 1 数到 n
  - 用户输入循环：处理持续的用户输入
  - 求和循环：累加数字总和
  - 菜单循环：显示菜单直到用户退出
  - 条件循环：根据布尔值控制

- **无限循环**
  - `while(true)` 的特殊用法
  - 适用场景：事件驱动程序、服务器程序、游戏主循环
  - 必须有退出机制：`break`、`return`、程序退出条件

- **新知识点**
  - `std::cin` 在循环中使用（持续输入）
  - 循环中的条件更新
  - 避免无限循环的最佳实践

#### 🎓 教学特色

- **类比**：while 循环像"只要不下雨就一直散步"
- **类比**：循环变量像计数器
- **类比**：无限循环像卡住的机器

### 07-for-loop.md - for 循环详解

#### 🔑 核心知识点

- **for 循环基础**
  - 语法：`for (初始化; 条件; 更新) { ... }`
  - 初始化、条件、更新都在一行
  - 适合确定次数的重复任务

- **三个部分**
  - **初始化**：循环开始时执行一次，初始化循环变量
  - **条件**：每次循环前检查，为真则继续
  - **更新**：每次循环后执行，改变循环变量

- **for vs while 对比**
  - while：初始化、条件、更新分散在三处
  - for：三个部分集中在一行，更简洁
  - 类比：while 像分散的厨房，for 像一体的工具箱

- **循环变量作用域**
  - 循环变量只存在于循环内部
  - 循环结束后无法访问
  - 类比：在教室里才能用椅子，出教室用不了

- **跳步循环**
  - `i += 2`：步长为 2
  - `i += 3`：步长为 3
  - 跳过某些值

- **倒序循环**
  - `for (int i = 5; i >= 1; i--)`：从 5 到 1

- **嵌套循环**
  - 外层循环控制行，内层循环控制列
  - 总执行次数 = 外层次数 × 内层次数
  - 类比：给教室排座位，外层处理行，内层处理列

- **循环控制语句（break 和 continue）**
  - `break`：立即跳出当前循环（找到目标、错误发生、满足退出条件）
  - `continue`：跳过本次循环的剩余部分（跳过某些值、过滤数据）
  - 类比：break 像"找到想要的，停止搜索"；continue 像"这个不对，下一个"

- **重要规则**
  - 初始化、条件、更新都在 for 括号内
  - 循环变量的作用域仅限于循环内部
  - 可以省略某些部分：`for (; i < 5;)`、`for (;;)`
  - break 和 continue 的使用场景和区别

- **常见应用场景**
  - 计数循环：打印数字序列
  - 倒序循环：倒计时
  - 字符串打印：重复打印文本
  - 跳跃式循环：输出偶数
  - 求和循环：累加计算
  - 嵌套循环：打印表格（如九九乘法表）
  - 循环控制：查找、过滤数据

- **新知识点**
  - 数组初步概念：`std::string users[5]`
  - 数组访问：`users[0]`、`users[1]`
  - 数组索引从 0 开始（0, 1, 2, 3, 4）

#### 🎓 教学特色

- **类比**：for 循环像"从 1 数到 10"（确定次数）
- **类比**：嵌套循环像"给教室排座位"
- **类比**：break 像"找到想要的，停止搜索"
- **类比**：continue 像"跳过这一项，继续下一项"

### 08-switch.md - switch 分支详解

#### 🔑 核心知识点

- **switch 分支基础**
  - 语法：`switch (表达式) { case 值: ... break; default: ... }`
  - 根据表达式的值从多个选项中选择执行
  - 类比：自动售货机，按不同按钮得到不同商品

- **组成部分**
  - **switch 表达式**：必须是整数类型或枚举类型
  - **case 标签**：每个 case 后面跟常量值，不能使用变量
  - **break 语句**：跳出 switch，避免 case 穿透
  - **default 分支**：可选，处理所有 case 都不匹配的情况

- **case 穿透**
  - 多个 case 之间没有 break 会一起执行后续代码
  - 故意的穿透：多个值共享同一段代码
  - 意外的穿透：忘记写 break（常见错误）
  - 类比：多个按钮对应同样的功能

- **重要规则**
  - **表达式类型限制**：只能是整数类型或枚举类型
    - 正确：`switch (choice)` - choice 是 int
    - 正确：`switch (grade)` - grade 是 char
    - 错误：`switch (str)` - str 是 std::string
  - **case 标签必须是常量**：不能使用变量
    - 正确：`case 1:`、`case 2:`、`case 'A':`
    - 错误：`case i:`（i 是变量）
  - **break 的必要性**：每个 case 后面通常要有 break
  - **类比**：switch 像电梯按钮，按下楼层号跳转到对应楼层

- **switch vs if-else if**
  - switch：适合离散的固定值（菜单选项、状态码、等级）
  - if-else if：适合范围值或复杂条件（分数区间、组合条件）
  - 选择原则：离散固定值用 switch，范围或复杂条件用 if-else if

- **常见应用场景**
  - 菜单选择：根据用户输入执行不同功能
  - 状态机：根据状态执行不同操作
  - 成绩等级：将分数转换为等级
  - 消息类型处理：根据消息类型执行不同处理
  - 选项处理：字符或数字选择

- **新知识点**
  - **枚举类型提示**：将在后续详细讲解，非常适合与 switch 配合使用
  - **状态机概念**：根据不同的状态执行不同的处理

#### 🎓 教学特色

- **类比**：switch 像自动售货机
- **类比**：case 穿透像"多个按钮对应同样功能"
- **类比**：break 像"路标，有路标就停下"
- **类比**：switch vs if-else if 像"单选 vs 范围选择"

### 09-array-basics.md - 数组基础详解

  - 方式 1：声明时初始化 `int arr[5] = {1, 2, 3, 4, 5};`

  - 方式 3：声明后赋值

- **数组访问和修改**
  - 使用索引访问：`arr[0]`、`arr[1]`...
  - 索引范围：`[0, size-1]`
  - 可以修改元素：`arr[0] = 10;`

- **数组遍历**
  - 使用 for 循环遍历
  - 循环变量从 0 开始：`for (int i = 0; i < size; i++)`

- **数组操作**

  - 查找最大值/最小值

  - 查找元素

- **重要规则**
  - 数组大小必须是常量

  - 数组元素类型必须一致
  - 数组大小在声明时确定，不能改变

- **与循环结合**
  - 遍历数组元素
  - 统计数组数据
  - 查找和搜索
  - 数组操作（反转、排序等）

#### 🔑 核心知识点

- **vector 概念**
  - 动态数组容器，可以自动调整大小
  - 类比：像可伸缩的仓库，不需要提前知道要存多少东西
  - 需要头文件：`#include <vector>`

- **模板概念**
  - vector 是模板类：`std::vector<类型>`
  - 类比：像通用模具，通过指定类型生成特定容器
  - 示例：`std::vector<int>`（整数容器）、`std::vector<std::string>`（字符串容器）

- **vector 初始化（5 种方式）**
  - 方式 1：空 vector `std::vector<int> vec;`
  - 方式 2：指定大小 `std::vector<int> vec(5);`
  - 方式 3：指定大小和值 `std::vector<int> vec(5, 10);`
  - 方式 4：从数组初始化 `std::vector<int> vec(arr, arr + 5);`
  - 方式 5：列表初始化（C++11）`std::vector<int> vec = {1, 2, 3, 4, 5};`

- **基本操作**
  - `push_back(x)` - 在末尾添加元素
  - `pop_back()` - 删除最后一个元素
  - `size()` - 返回元素数量（返回 `size_t` 类型）
  - `empty()` - 判断是否为空
  - `vec[i]` - 访问索引为 i 的元素

- **类型安全**
  - `size()` 返回 `size_t` 类型（无符号整数）
  - 循环遍历建议使用 `size_t i` 而不是 `int i`
  - 类型转换：`static_cast<int>(i)` 用于输出等场景

- **迭代器（初步概念）**
  - 迭代器：指向容器中元素位置的标记
  - `vec.begin()` - 指向第一个元素的迭代器
  - `vec.end()` - 指向最后一个元素后面的迭代器（结束标记）
  - `vec.begin() + i` - 指向第 i 个元素的迭代器
  - `*it` - 通过迭代器访问元素值
  - 类比：像门牌号或指向房子的指针

- **进阶操作（insert 和 erase）**
  - `insert(pos, x)` - 在迭代器 `pos` 指向位置之前插入元素 `x`
  - `erase(pos)` - 删除迭代器 `pos` 指向的元素，返回下一个有效迭代器
  - 遍历删除的正确做法：`it = vec.erase(it);`（必须接收返回值）
  - 迭代器失效：删除后原迭代器失效，必须用返回值更新

- **重要特性**
  - 动态大小：可以随时添加和删除元素
  - 类型安全：模板类型检查
  - 自动内存管理：自动分配和释放内存
  - 高效操作：末尾操作非常快速

- **vector vs 数组**
  - 数组：大小固定，栈上分配，不需要头文件
  - vector：大小可动态调整，堆上分配，需要 `#include <vector>`
  - 选择原则：确定大小用数组，不确定用 vector

#### 🎓 教学特色

- **类比**：vector 像可伸缩的仓库，数组像固定大小的房子
- **类比**：模板像通用模具，可以装不同东西
- **类比**：迭代器像门牌号或指向房子的指针

### 11-string-advanced.md - 字符串进阶操作

#### 🔑 核心知识点

- **字符串方法**
  - `length()` / `size()` - 返回字符串字节数（`size_t` 类型）
  - `empty()` - 判断是否为空
  - `str[i]` - 访问第 i 个字节（注意：对中文字符不完全适用）
  - `str + "text"` / `str += "text"` - 字符串拼接
  - `str == "text"` / `str < "text"` - 字符串比较

- **字符串查找**
  - `find("text")` - 查找子串，返回 `size_t` 类型的位置
  - 返回值：找到返回位置（索引），未找到返回 `std::string::npos`
  - 判断是否找到：`if (str.find("text") != std::string::npos)`
  - 可以查找单个字符或子串

- **子串提取**
  - `substr(起始位置, 长度)` - 提取指定长度的子串
  - `substr(起始位置)` - 从起始位置提取到末尾
  - 返回新字符串，不修改原字符串
  - 类比：像从书中剪下一段文字

- **字符串长度和编码**
  - `length()` 返回字节数，不是字符个数
  - ASCII 编码：英文字符占 1 字节
  - UTF-8 编码：中文字符占 3 字节
  - 示例：`"Hello"` 长度为 5（字节），`"张三"` 长度为 6（字节）
  - 重要提示：`str[i]` 访问的是字节，对中文字符需要特殊处理

- **字符串访问**
  - 索引从 0 开始：`str[0]` 是第一个字符
  - `str[str.length() - 1]` - 最后一个字符
  - 索引越界危险：可能导致未定义行为

- **输入方法**
  - `std::cin >> str` - 只能读取到第一个空格前
  - `std::getline(std::cin, str)` - 读取一整行（包括空格）
  - `std::getline()` 功能：读取直到遇到换行符

- **常见应用**
  - 字符串验证（长度、空格检查）
  - 字符串解析（提取用户名、域名等）
  - 字符串反转
  - 字符统计

#### 🎓 教学特色

- **类比**：字符串基础像写字，进阶操作像编辑文章
- **类比**：字符串方法像工具箱里的工具
- **类比**：`substr()` 像从书中剪下一段文字
- **类比**：`find()` 像在文章里找某个词

### 12-functions.md - 函数基础详解

#### 🔑 核心知识点

- **函数概念**
  - 函数的定义和作用
  - 将代码封装成独立的功能模块
  - 可以重复调用，避免代码重复
  - 类比：函数像工具箱，装着特定的工具（代码）

- **函数定义语法**
  - 语法：`返回类型 函数名(参数列表) { ... }`
  - 返回类型：`int`、`double`、`std::string`、`void`（无返回值）
  - 函数名：推荐使用 `camelCase` 命名规范（与 Qt 框架一致）
  - 参数列表：可以有多个参数，用逗号分隔
  - 函数体：具体的执行代码
  - `return` 语句：返回结果（`void` 函数可以不返回）

- **函数调用语法**
  - 语法：`函数名(实参列表);`
  - 实参：调用时传入的实际值
  - 形参：函数定义中的参数变量
  - 类比：就像使用自动售货机，投入实际的硬币（实参），按下按钮（调用），得到商品（返回值）

- **函数类型**
  - 无参数、无返回值：`void greet()`
  - 有参数、有返回值：`int add(int a, int b)`
  - 无参数、有返回值：`int getTen()`
  - 字符串处理函数：`std::string formatMessage(std::string name, std::string message)`

- **函数声明和定义分离**
  - 函数声明（函数原型）：`返回类型 函数名(参数列表);`
  - 函数定义：实现函数的具体代码
  - 允许在 `main()` 之前声明，在 `main()` 之后定义
  - 提高代码可读性

- **参数传递（值传递）**
  - 实参的值会复制给形参
  - 传递的是值的副本，不是变量本身
  - 修改形参不会影响实参（后续会学习引用传递）
  - 类比：就像复印文件，修改复印件不影响原件

- **返回值**
  - 使用 `return` 语句返回结果
  - `void` 函数可以不写 `return`，或写 `return;`
  - 函数遇到 `return` 会立即结束执行
  - 可以返回各种类型：`int`、`double`、`std::string`、`bool` 等

- **函数作用域**
  - 函数内部的变量只在函数内有效
  - 形参和函数内定义的变量都是局部变量
  - 函数外无法访问函数内的变量
  - 类比：就像房间里的东西只在房间里能用，出了房间就看不到了

- **函数命名规范**
  - 推荐使用 `camelCase`（小驼峰命名法）
  - 第一个单词首字母小写，后续单词首字母大写
  - 示例：`calculateSum()`、`getUserName()`、`printMessage()`
  - 说明：与 Qt 框架命名风格一致（如 `QString::isEmpty()`）
  - 注意：C++ 标准库使用 `snake_case`（如 `std::getline()`），但自定义函数建议使用 `camelCase`

- **函数的作用和价值**
  - 代码复用：同一段代码可以多次调用，避免重复
  - 模块化：将复杂问题分解成多个函数，代码结构清晰
  - 易于维护：修改功能只需修改一个函数
  - 可读性：函数名描述了功能，代码更易理解

- **常见应用场景**
  - 计算工具函数（加、减、乘、除）
  - 数据验证函数（验证用户名长度、检查消息是否为空）
  - 字符串处理函数（格式化消息、转换大小写）
  - 判断函数（判断是否为偶数）

- **重要规则**
  - 函数必须在使用前定义，或者先声明后定义
  - 实参的数量和类型必须与形参匹配
  - 函数名必须遵循标识符命名规则
  - 函数内部的局部变量与函数外部的变量是独立的

#### 🎓 教学特色

- **类比**：函数像工具箱，装着特定的工具（代码）
- **类比**：函数调用像使用自动售货机，投入参数得到返回值
- **类比**：值传递像复印文件，修改复印件不影响原件
- **类比**：函数作用域像房间的私有空间，房间里的东西只在房间里能用
- **类比**：函数命名应该清楚描述函数做什么，就像给工具贴标签

### 13-pointers.md - 指针详解

#### 🔑 核心知识点

- **指针概念**
  - 指针定义：存储变量内存地址的变量
  - 类比：指针像门牌号，变量像房子
  - 内存地址：每个变量在内存中都有唯一地址
  - 解引用：通过指针访问值

- **指针声明**
  - 语法：`数据类型* 指针变量名;`
  - 推荐风格：`int* ptr`（强调类型是指针）
  - 指针类型：`int*`、`double*`、`std::string*` 等

- **取地址操作符（&）**
  - `&变量名` - 获取变量的内存地址
  - 类比：问"这个房子在哪里"，得到门牌号
  - 示例：`int* ptr = &num;`

- **解引用操作符（\*）**
  - `*指针变量名` - 通过指针访问值
  - 声明时的 `*` 表示类型，使用时的 `*` 表示解引用
  - 类比：通过门牌号找到房子并查看里面的东西
  - 示例：`*ptr = 10;`、`int value = *ptr;`

- **空指针**
  - `nullptr` - C++11 引入的空指针字面量
  - 表示指针不指向任何对象
  - 空指针的值通常是 `0x0`
  - 解引用空指针会导致程序崩溃

- **指针在函数中的使用**
  - 指针传递：传递地址，函数可以修改实参
  - 调用时需要传递变量的地址（`&x`、`&y`）
  - 函数内部需要通过解引用（`*a`、`*b`）访问和修改值
  - 与值传递对比：值传递不能修改实参，指针传递可以

- **指针的常见陷阱**
  - 未初始化的指针：危险，可能导致未定义行为
  - 悬空指针（野指针）：使用已释放内存的指针
  - 空指针解引用：解引用空指针会导致程序崩溃
  - 最佳实践：始终初始化指针、使用前检查、释放后置空

- **指针的应用场景**
  - 可选参数：函数参数可能为空时使用指针
  - 查找函数：在数组中查找元素，返回指向元素的指针
  - 动态内存管理：分配和管理动态内存（将在后续章节学习）
  - 底层操作：需要直接访问内存地址的场景

- **重要规则**
  - 指针必须在声明时初始化（推荐初始化为 `nullptr`）
  - 指针可以重新指向其他变量
  - 指针可以为空（`nullptr`）
  - 解引用前必须检查指针是否为空

#### 🎓 教学特色

- **类比**：指针像门牌号，变量像房子
- **类比**：取地址像问"这个房子在哪里"
- **类比**：解引用像通过门牌号找到房子并查看里面的东西
- **类比**：空指针像不存在的门牌号

### 14-references.md - 引用详解

#### 🔑 核心知识点

- **引用概念**
  - 引用定义：变量的别名，是已存在变量的另一个名字
  - 类比：像同一个人的两个名字
  - 与指针的区别：指针像门牌号，引用像同一个人的另一个名字
  - 内存模型：引用不占用额外的内存空间（编译器优化）

- **引用声明**
  - 语法：`数据类型& 引用变量名 = 原变量名;`
  - 引用必须在声明时初始化，不能先声明后初始化
  - 引用不能重新绑定到其他变量
  - 引用就是原变量的别名，操作引用就是操作原变量

- **引用使用**
  - 直接使用，无需解引用（与指针不同）
  - 通过引用修改值：`ref = 200;` 等价于 `value = 200;`
  - 引用和原变量的地址相同：`&ref == &value`

- **const 引用**
  - 语法：`const 数据类型& 引用变量名 = 原变量名;`
  - 只读引用，不能通过引用修改原变量
  - 使用场景：传递大对象作为函数参数，只读访问
  - 避免复制大对象的开销，同时保证数据安全

- **引用在函数中的使用（最核心的应用）**
  - **引用作为函数形参**：实际开发中最常见、最重要的应用
  - 引用传递：传递的是别名，直接操作原变量，语法更简洁
  - 调用时直接传递变量（不需要 `&`），编译器自动处理
  - 函数内部直接使用，无需解引用
  - 与值传递对比：值传递复制数据，引用传递不复制

- **const 引用传递（推荐）**
  - 使用 const 引用传递大对象，避免复制
  - 性能提升：10-100 倍（取决于对象大小）
  - 推荐：对于所有非基本类型的参数，优先使用 const 引用传递
  - 基本类型可以值传递（性能差异不大）

- **引用的应用场景**
  - **场景 1：引用作为函数形参（最核心）** - 让函数直接操作原始数据，避免复制
  - **场景 2：避免大对象复制** - const 引用的典型应用
  - **场景 3：修改函数参数** - 非 const 引用的典型应用
  - **场景 4：返回值优化** - 返回引用，避免复制（注意不能返回局部变量引用）
  - **场景 5：在循环中使用引用** - 范围 for 循环中使用引用，提高效率
  - **场景 6：与 STL 容器配合使用** - 传递容器参数、遍历容器元素

- **范围 for 循环（range-based for loop）**
  - C++11 引入的新语法
  - 语法：`for (类型 变量名 : 容器)`
  - 自动遍历容器中的每个元素
  - 在循环中使用引用：`for (const T& item : container)` 避免复制

- **引用 vs 指针**
  - 初始化：引用必须初始化，指针可以不初始化（但危险）
  - 重新绑定：引用不能重新绑定，指针可以指向其他变量
  - 空值：引用不能为空，指针可以为 `nullptr`
  - 语法：引用直接使用，指针需要解引用
  - 内存占用：引用不占用额外内存，指针占用内存（存储地址）
  - 安全性：引用更安全（不能为空），指针需要检查空指针
  - 适用场景：引用用于函数参数传递（推荐），指针用于可选参数、动态内存

- **引用的常见陷阱**
  - 引用未初始化：错误，引用必须初始化
  - 引用绑定到空值：错误，引用不能为空
  - 返回局部变量的引用：危险，局部变量在函数结束后被销毁
  - 误认为引用可以重新绑定：`ref = value2` 不是重新绑定，而是赋值

- **最佳实践**
  - 始终在声明时初始化引用
  - 不要返回局部变量的引用
  - 优先使用 const 引用传递参数
  - 只在需要修改时才使用非 const 引用
  - 对于函数参数传递，优先使用引用，特别是 const 引用

- **重要规则**
  - 引用必须在声明时初始化
  - 引用不能重新绑定
  - 引用不能为空
  - 引用就是原变量的别名，地址相同

#### 🎓 教学特色

- **类比**：引用像同一个人的另一个名字
- **类比**：与指针的区别：指针像门牌号，引用像同一个人的另一个名字
- **类比**：const 引用像给文件起另一个名字，但只能读，不能写
- **类比**：引用传递像给文件另一个名字，用这个名字修改就是修改原件

### 15-memory-management.md - 内存管理详解

#### 🔑 核心知识点

- **内存管理概念**
  - 内存管理定义：程序运行时对内存的分配和释放
  - 两种方式：手动内存管理（new/delete）和自动内存管理（智能指针）
  - 类比：栈内存像自动售货机，堆内存像仓库

- **栈内存 vs 堆内存**
  - 栈内存：由编译器自动分配和释放，速度快但大小有限，适合局部变量
  - 堆内存：由程序员手动分配和释放，速度较慢但大小灵活，适合动态数据
  - 对比：分配方式、释放方式、速度、大小、适用场景

- **动态内存分配（new/delete）**
  - `new` 操作符：在堆上分配内存，返回指针
    - 语法：`new 数据类型`、`new 数据类型(初始值)`、`new 数据类型[大小]`
    - 分配失败会抛出异常（`std::bad_alloc`）
  - `delete` 操作符：释放堆内存
    - 语法：`delete 指针变量`（单个对象）、`delete[] 指针变量`（数组）
    - 重要规则：配对使用、数组用 `delete[]`、释放后置空、不能重复释放

- **内存泄漏问题**
  - 内存泄漏定义：分配了内存但忘记释放，导致内存无法被回收
  - 常见场景：忘记释放、提前返回、异常导致未释放
  - 防止方法：配对使用、释放后置空、使用智能指针、遵循 RAII 原则

- **智能指针（推荐方式）**
  - **unique_ptr（独占所有权）**
    - 独占所有权，不能复制，只能移动
    - 自动释放内存，无需手动 `delete`
    - 性能开销小，几乎与原始指针相同
    - 使用 `std::make_unique` 创建
  - **shared_ptr（共享所有权）**
    - 共享所有权，可以复制
    - 使用引用计数管理内存，当计数为 0 时自动释放
    - 性能开销略大于 `unique_ptr`（需要维护引用计数）
    - 使用 `std::make_shared` 创建
  - **选择原则**：优先使用 `unique_ptr`，需要共享时使用 `shared_ptr`

- **RAII 原则**
  - RAII 定义：资源获取即初始化，将资源生命周期与对象生命周期绑定
  - 核心思想：利用 C++ 对象的自动清理特性，自动管理资源
  - 优势：自动管理资源、异常安全、代码更简洁
  - 类比：就像自动门，进入时自动打开，离开时自动关闭

- **常见陷阱和注意事项**
  - 忘记释放内存：导致内存泄漏
  - 重复释放：未定义行为
  - 数组释放错误：`new[]` 必须用 `delete[]` 释放
  - 使用已释放的内存：未定义行为
  - 最佳实践：优先使用智能指针、配对使用 new/delete、释放后置空、遵循 RAII 原则

#### 🎓 教学特色

- **类比**：栈内存像自动售货机，堆内存像仓库
- **类比**：内存泄漏像从仓库借了东西忘记归还
- **类比**：智能指针像自动归还系统
- **类比**：unique_ptr 像一把钥匙只能给一个人，shared_ptr 像多个人可以共享同一把钥匙
- **类比**：RAII 像自动门，进入时自动打开，离开时自动关闭

### 16-struct.md - 结构体详解

#### 🔑 核心知识点

- **结构体概念**
  - 结构体定义：将多个不同类型的数据组合在一起，形成一个新的数据类型
  - 类比：像一张信息卡片，上面有多个字段，所有信息都属于同一个对象
  - 数据组织：把相关的数据放在一起，方便管理和使用

- **结构体定义**
  - 语法：`struct 结构体名称 { 成员变量列表 };`
  - 命名规范：结构体名称使用 `PascalCase`，成员变量使用 `camelCase`
  - 结构体定义必须以分号 `;` 结束
  - 每个成员变量都有自己的数据类型

- **结构体变量声明和使用**
  - 声明：`结构体名称 变量名;`
  - 访问成员：使用点号 `.` 访问成员变量（`变量名.成员变量名`）
  - 可以读取和修改成员变量的值
  - 每个结构体变量都有自己独立的成员变量副本

- **结构体初始化**
  - 方式 1：声明后逐个赋值（最常用）
  - 方式 2：列表初始化（C++11，推荐）- `User user = {"张三", 25, true};`
  - 方式 3：声明时初始化（C++11）- `User user{"张三", 25, true};`
  - 列表初始化必须按照结构体定义中成员变量的顺序提供值

- **结构体作为函数参数**
  - **值传递**：复制整个结构体，性能较差，不推荐用于大结构体
  - **const 引用传递**：只读访问，避免复制，性能好（最推荐）
  - **非 const 引用传递**：可以修改原始结构体，避免复制（推荐用于需要修改的场景）
  - **指针传递**：使用 `->` 访问成员，可以表示可选参数
  - **选择原则**：优先使用 const 引用传递，需要修改时使用非 const 引用或指针

- **结构体数组和容器**
  - 结构体数组：`User users[3];` - 固定大小
  - 结构体 vector（推荐）：`std::vector<User> users;` - 动态大小
  - 使用范围 for 循环遍历结构体 vector
  - 推荐使用 `vector` 而不是数组

- **常见陷阱和注意事项**
  - 忘记结构体定义后的分号：错误
  - 列表初始化顺序错误：必须按定义顺序
  - 访问不存在的成员变量：错误
  - 最佳实践：使用 const 引用传递、使用列表初始化、合理组织数据、遵循命名规范

#### 🎓 教学特色

- **类比**：结构体像一张信息卡片，成员变量像卡片上的字段
- **类比**：结构体变量像填写好的一张卡片
- **类比**：数据组织像把一个人的所有信息放在一张卡片上

### 17-enum.md - 枚举类型详解

#### 🔑 核心知识点

- **枚举类型概念**
  - 枚举定义：定义一组命名常量的数据类型
  - 类比：像交通信号灯的颜色选项（红、黄、绿），或者一周的星期（周一、周二、周三...）
  - 类型安全：使用枚举可以避免使用错误的常量值

- **枚举定义**
  - 语法：`enum 枚举名称 { 枚举值1, 枚举值2, ... };`
  - 命名规范：枚举名称和枚举值使用 `PascalCase` 命名规范
  - 枚举值默认值：第一个枚举值默认为 `0`，后续依次递增
  - 手动指定值：可以手动指定枚举值的数值（如 `Low = 1`）

- **枚举变量声明和使用**
  - 声明：`枚举名称 变量名;`
  - 使用枚举值：`变量名 = 枚举名称::枚举值;`（C++11 推荐）
  - 枚举变量只能赋值为枚举中定义的值
  - 直接输出枚举变量会显示其对应的整数值

- **枚举与 switch 配合使用**
  - 枚举是 switch 语句的理想选择
  - 使用 switch 处理枚举值，代码更清晰
  - 类型安全：只能使用枚举中定义的值
  - 易于维护：添加新的枚举值，编译器会提示需要处理的新 case

- **枚举作为函数参数**
  - 值传递：枚举本质上是整数，值传递已足够高效
  - const 引用传递：也可以使用，与结构体传递方式保持一致
  - 提供类型安全的参数传递

- **枚举在结构体中的应用**
  - 枚举经常与结构体配合使用
  - 为结构体的成员变量提供类型安全的选项
  - 使用 switch 处理结构体中的枚举成员

- **常见陷阱和注意事项**
  - 忘记枚举定义后的分号：错误
  - 使用未定义的枚举值：错误
  - 直接使用整数赋值：不推荐
  - 最佳实践：使用枚举名称限定、与 switch 配合使用、合理命名、集中管理

#### 🎓 教学特色

- **类比**：枚举像交通信号灯的颜色选项或一周的星期
- **类比**：枚举值像清单上的每个选项
- **类比**：枚举变量只能取枚举中定义的值，就像只能选择清单上存在的选项

### 18-classes-objects.md - 类和对象详解

#### 🔑 核心知识点

- **类和对象概念**
  - 类定义：将数据和操作数据的函数组合在一起，形成新的数据类型
  - 对象定义：用类创建的具体实例
  - 类比：类像汽车设计图，对象像根据设计图制造的具体汽车
  - 封装：将数据和操作数据的函数放在一起，并通过访问控制（public/private）保护数据

- **类与结构体的关系**
  - 主要区别：默认访问权限（struct 默认 public，class 默认 private）
  - struct 用于简单的数据组织，class 用于面向对象编程
  - 结构体也支持成员函数、构造函数和析构函数（但 16-struct.md 专注于数据组织）

- **类定义语法**
  - 语法：`class 类名称 { public: ... private: ... };`
  - 访问控制：`public`（公开）、`private`（私有）
  - 命名规范：类名使用 `PascalCase`
  - 类定义必须以分号 `;` 结束

- **成员变量和成员函数**
  - 成员变量：类中的数据，用于存储对象的状态
  - 成员函数：类中的函数，用于操作成员变量或提供功能
  - `const` 成员函数：表示函数不会修改成员变量（只读函数）

- **对象创建和使用**
  - **栈对象**：`类名称 对象名;` - 在栈上创建，自动管理，推荐使用
  - **堆对象（new/delete）**：`类名称* 指针名 = new 类名称();` - 需要手动 delete
  - **堆对象（智能指针）**：`std::unique_ptr<类名称> 指针名 = std::make_unique<类名称>();` - 自动管理，推荐使用
  - 成员访问：对象使用 `.` 操作符，指针使用 `->` 操作符
  - `指针->成员` 等价于 `(*指针).成员`

- **构造函数**
  - 构造函数定义：函数名与类名相同，没有返回值（连 void 都不写）
  - 在创建对象时自动调用，用于初始化对象的成员变量
  - 可以重载（可以有多个构造函数，参数不同）
  - 函数重载：同一个函数名可以有多个不同的版本，通过参数类型或数量来区分

- **析构函数**
  - 析构函数定义：函数名是 `~类名称`（波浪号 + 类名），没有返回值，没有参数
  - 在对象销毁时自动调用，用于清理资源
  - 每个类只能有一个析构函数

- **封装概念澄清**
  - 数据组织：将相关数据放在一起（结构体也可以做到）
  - 封装（Encapsulation）：不仅将数据和函数放在一起，更重要的是通过访问控制（private/public）来保护数据，隐藏实现细节
  - 为什么结构体不算封装：结构体默认所有成员都是 public，无法实现数据保护
  - 类的封装：使用 private 保护数据，使用 public 提供接口，这才是真正的封装

#### 🎓 教学特色

- **类比**：类像汽车的设计图，对象像根据设计图制造出的具体汽车
- **类比**：成员变量像设计图中的部件（发动机、轮胎等）
- **类比**：成员函数像设计图中的功能（启动、加速、刹车等）
- **类比**：封装像把汽车的部件和功能都设计在一张图纸上，并且有些部件是公开的（如车门），有些是私有的（如发动机内部结构）
- **类比**：public 像公共区域，任何人都可以进入；private 像私人房间，只有类自己可以使用

### 19-encapsulation.md - 封装详解

#### 🔑 核心知识点

- **封装概念**
  - 封装定义：将数据和操作数据的函数组合在一起，并通过访问控制（private/public）来保护数据，隐藏实现细节，只暴露必要的接口
  - 类比：像银行的保险箱，重要的数据（如密码、余额）被锁在保险箱里（private），只有通过特定的接口（如 ATM 机、柜台）才能访问

- **为什么需要封装**
  - 数据保护：防止数据被意外修改或访问
  - 数据验证：可以在 setter 中验证数据的合法性
  - 接口控制：只暴露必要的接口，隐藏实现细节

- **访问控制详解**
  - **public（公开）**：可以在类外部访问的成员，用于提供类的接口
  - **private（私有）**：只能在类内部访问的成员，用于保护敏感数据和隐藏实现细节
  - **protected（保护）**：可以在类内部和派生类中访问的成员（将在继承章节详细讲解）

- **Getter 和 Setter 模式**
  - **Getter（获取器）**：用于获取私有成员变量值的公开函数
    - 命名规范：通常以 `get` 开头，如 `getName()`、`getAge()`
    - 通常使用 `const` 修饰（不修改成员变量）
    - 返回值而不是引用，避免外部修改
  - **Setter（设置器）**：用于设置私有成员变量值的公开函数
    - 命名规范：通常以 `set` 开头，如 `setName()`、`setAge()`
    - 可以在设置前验证数据的合法性
    - 可以记录修改日志、触发相关操作

- **封装的优势**
  - 数据保护：私有成员变量无法被外部直接修改
  - 接口设计：通过 public 函数提供清晰的接口，隐藏实现细节
  - 代码组织：数据和操作数据的函数放在一起，职责明确

- **封装的最佳实践**
  - 数据成员设为 private：除非有特殊原因，否则成员变量应该设为 private
  - 提供必要的 Getter/Setter：只为需要外部访问的成员变量提供 getter/setter
  - 在 Setter 中验证数据：确保数据的有效性
  - 使用 const 修饰 Getter：表示不会修改对象
  - 避免返回引用：getter 通常返回值而不是引用，避免外部修改

#### 🎓 教学特色

- **类比**：封装像银行的保险箱，重要的数据被锁在保险箱里（private），只有通过特定的接口（如 ATM 机、柜台）才能访问
- **类比**：数据隐藏像把贵重物品锁在保险箱里，外部无法直接访问
- **类比**：接口设计像银行提供 ATM 机、柜台等服务，而不是直接打开保险箱
- **类比**：getter/setter 像银行的工作人员，通过特定的流程（getter 获取、setter 设置）来操作数据

### 20-inheritance.md - 继承详解

#### 🔑 核心知识点

- **继承概念**
  - 继承定义：允许一个类（派生类）继承另一个类（基类）的成员变量和成员函数，实现代码复用和功能扩展
  - 类比：像父子关系，孩子（派生类）继承了父母（基类）的特征和能力，同时可以有自己的特点
  - 基类（父类）：被继承的类，定义了通用的特征和行为
  - 派生类（子类）：继承基类的类，可以添加新的特征和行为，也可以修改继承来的行为

- **为什么需要继承**
  - 代码复用：避免重复编写相同的代码
  - 易于维护：修改基类，所有派生类自动继承修改
  - 易于扩展：派生类可以添加新功能，不影响基类

- **继承语法**
  - 语法：`class 派生类名称 : 继承方式 基类名称 { ... };`
  - 继承方式：`public` 继承（最常用）、`private` 继承、`protected` 继承
  - 派生类自动拥有基类的所有 public 和 protected 成员
  - 派生类可以添加新的成员变量和成员函数

- **访问控制与继承**
  - **protected（保护）**：可以在类内部和派生类中访问的成员，但在类外部不能访问
  - 访问权限对比：
    - public：类内部、派生类、类外部都可以访问
    - protected：类内部和派生类可以访问，类外部不能访问
    - private：只有类内部可以访问
  - 使用 protected 的原因：基类的某些成员需要被派生类访问，但不应该被外部访问

- **构造函数和析构函数**
  - **构造函数调用顺序**：先调用基类的构造函数，再调用派生类的构造函数
  - **析构函数调用顺序**：先调用派生类的析构函数，再调用基类的析构函数（与构造函数相反）
  - **初始化列表语法**：`构造函数(参数) : 基类构造函数(参数), 成员变量(值) { 构造函数体 }`
    - 作用：在构造函数体执行之前初始化成员变量和调用基类构造函数
    - 示例：`Student(const std::string& n, int a, const std::string& id) : Person(n, a), studentId(id) {}`
    - 为什么使用初始化列表：这是调用基类构造函数和初始化成员变量的标准方式，比在构造函数体中赋值更高效

- **类内函数定义**
  - 在 C++ 中，可以直接在类定义中实现函数，函数体写在函数声明后面
  - 语法：`返回类型 函数名(参数) { 函数体 }`
  - 适用场景：对于简单的函数（如 getter/setter），这种写法简洁明了
  - 说明：复杂函数可以声明和定义分开（将在后续章节介绍）

- **继承的优势**
  - 代码复用：相同的代码只需在基类中定义一次
  - 功能扩展：派生类可以添加新的成员变量和成员函数，可以重写基类的成员函数
  - 类层次设计：通过继承建立清晰的类层次结构

- **继承的最佳实践**
  - 合理使用 protected：将需要被派生类访问但不需要被外部访问的成员设为 protected
  - 使用 public 继承：除非有特殊原因，否则使用 public 继承
  - 在派生类构造函数中调用基类构造函数：显式调用基类构造函数，确保正确初始化

- **继承 vs 组合**
  - 继承：是"是一个"关系（如 Student 是一个 Person），用于代码复用和功能扩展
  - 组合：是"有一个"关系（如 Car 有一个 Engine），用于对象包含
  - 区别：继承是派生类是基类的一种，可以使用基类的所有 public 和 protected 成员；组合是一个类包含另一个类的对象作为成员，通过成员对象来使用其功能

#### 🎓 教学特色

- **类比**：继承像父子关系，孩子继承了父母的特征和能力，同时可以有自己的特点
- **类比**：基类像父母，定义了通用的特征和行为；派生类像孩子，可以添加新的特征和行为
- **类比**：protected 成员像家庭内部的共享物品，家庭成员（基类和派生类）都可以使用，但外人（类外部）不能直接使用
- **类比**：public 成员像公共设施，任何人都可以使用；private 成员像个人私人物品，只有自己（类内部）可以使用

### 21-polymorphism.md - 多态详解

#### 🔑 核心知识点

- **多态概念**
  - 多态定义：同一个接口可以有不同的实现方式，通过基类指针或引用调用派生类的函数，实现"一个接口，多种实现"
  - 类比：像"说话"这个行为，不同的人（派生类）说话的方式不同，但都是"说话"（同一个接口）
  - 虚函数：像"说话"这个行为的定义，告诉编译器"这个函数可能被派生类重新实现"
  - 动态绑定：在运行时根据对象的实际类型决定调用哪个函数，就像根据说话的人决定听谁的话

- **为什么需要多态**
  - 问题：如果不使用多态，需要为每个派生类编写不同的处理代码
  - 没有 virtual 关键字时：编译器根据指针的类型（基类指针）来决定调用哪个函数，而不是根据对象的实际类型（派生类对象）
  - 静态绑定：没有 virtual 时，编译器在编译时决定调用哪个函数
  - 动态绑定：使用 virtual 时，在运行时根据对象的实际类型决定调用哪个函数

- **虚函数**
  - 虚函数定义：使用 `virtual` 关键字声明的函数，允许派生类重写该函数，实现多态
  - 语法：`virtual 返回类型 函数名(参数) { ... }`
  - 只有基类中的虚函数才能被派生类重写

- **函数重写（override）**
  - 函数重写定义：派生类重新定义基类中的虚函数，提供自己的实现
  - 类比：就像孩子继承父母的"说话"能力，但可以用自己的方式说话（重写），而不是只能用父母的方式
  - 前提条件：只有基类中的虚函数（使用 `virtual` 关键字）才能被重写
  - `override` 关键字：C++11 引入，明确表示这是重写基类的虚函数，如果基类没有对应的虚函数，编译器会报错
  - 与函数重载的区别：
    - 函数重载：同一个类中，函数名相同但参数不同（编译时多态）
    - 函数重写：派生类重写基类的虚函数，函数签名相同（运行时多态）

- **虚析构函数**
  - 为什么需要虚析构函数：当使用基类指针删除派生类对象时，如果析构函数不是虚函数，只会调用基类的析构函数，派生类的析构函数不会被调用，可能导致资源泄漏
  - 规则：如果基类有虚函数，析构函数应该声明为虚函数
  - 语法：`virtual ~类名称() { ... }`

- **纯虚函数和抽象类**
  - **纯虚函数**：没有实现的虚函数，用 `= 0` 表示
    - 语法：`virtual 返回类型 函数名(参数) = 0;`
  - **抽象类**：包含至少一个纯虚函数的类，不能创建对象
    - 特点：不能创建抽象类的对象，派生类必须实现所有纯虚函数，否则也是抽象类
    - 作用和应用场景：
      - 定义接口规范：抽象类定义了一组接口（纯虚函数），强制派生类必须实现这些接口
      - 代码设计：在大型项目中，抽象类用于定义模块间的接口
      - 多态基础：抽象类作为基类，通过多态可以统一处理不同的派生类对象
      - 实际应用：图形系统（Shape 抽象类）、消息处理（Message 抽象类）、网络连接（Connection 抽象类）

- **多态的实现方式**
  - 栈对象+指针：`Dog dog; Animal* animal = &dog;`（推荐，更安全）
  - 堆对象：`Animal* animal = new Dog();`（需要手动 delete）
  - 两种方式都能实现多态，优先使用栈对象+指针的方式

- **成员访问操作符**
  - `.` 操作符：用于对象访问成员，如 `user1.name`、`user1.printInfo()`
  - `->` 操作符：用于指针访问成员，如 `user1->name`、`user1->printInfo()`
  - 等价关系：`指针->成员` 等价于 `(*指针).成员`
  - 使用场景：栈对象使用 `.` 操作符，堆对象/智能指针使用 `->` 操作符

- **多态的优势**
  - 统一接口：通过基类指针可以统一处理不同的派生类对象，不需要为每个派生类编写不同的处理代码
  - 动态绑定：在运行时根据对象的实际类型调用相应的函数（通过虚函数和函数重写实现）
  - 代码简化：通过函数重写，派生类可以提供自己的实现，但调用方式统一，代码更简洁
  - 易于扩展：添加新的派生类时，只需要重写虚函数，不需要修改调用代码

- **多态的最佳实践**
  - 使用虚析构函数：如果基类有虚函数，析构函数应该声明为虚函数
  - 使用 override 关键字：重写虚函数时使用 `override` 关键字，提高代码安全性
  - 合理使用抽象类：当需要定义接口时，使用抽象类（纯虚函数）

#### 🎓 教学特色

- **类比**：多态像"说话"这个行为，不同的人（派生类）说话的方式不同，但都是"说话"（同一个接口）
- **类比**：虚函数像"说话"这个行为的定义，告诉编译器"这个函数可能被派生类重新实现"
- **类比**：动态绑定像根据说话的人决定听谁的话
- **类比**：抽象类像"交通工具"的概念，定义了"启动"、"停止"等接口，但不能直接使用"交通工具"（不能创建对象）
- **类比**：派生类像"汽车"、"自行车"等具体交通工具，必须实现"启动"、"停止"等接口，才能使用
